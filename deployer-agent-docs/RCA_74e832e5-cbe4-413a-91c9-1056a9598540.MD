# RCA — POS receipt SMS shows "SMS: not_configured" (MSG91)

## Problem statement
After billing an invoice in POS, the app shows toast "SMS: not_configured" and no receipt SMS is sent. Backend `sms_service.py::_msg91_ready()` returns False (→ "not_configured") when `MSG91_AUTHKEY` OR `MSG91_SENDER_ID` is missing/empty in the running backend. Works in preview. Request: verify the PRODUCTION backend pod env / secrets.

## Scope
- Deployment: hair-hub-system (custom domain miracurl-suite.com)
- Active/serving run: 74e832e5-cbe4-413a-91c9-1056a9598540 (redeploy, success, completed 2026-09-27 16:45 UTC)
- Frontend: cloudflare. Backend: FastAPI. App is healthy/live.

## Findings (from list_secrets on the ACTIVE run — the env the prod pod actually runs with)
MSG91 variables in production:
- `MSG91_AUTHKEY` — PRESENT, non-empty ✓
- `MSG91_SENDER_ID` — PRESENT but **EMPTY** ✗  ← direct trigger of `_msg91_ready()==False`
- `MSG91_FLOW_ID` — PRESENT but **EMPTY** ✗
- `MSG91_TPL_OTP` — PRESENT, non-empty ✓
- `MSG91_TPL_BOOKING` — **ABSENT** ✗
- `MSG91_TPL_BILLING_V2` — **ABSENT** ✗
- No other `MSG91_TPL_*` keys exist in prod (only `MSG91_TPL_OTP`).

`SMS_PROVIDER` is set (non-empty). Twilio and WhatsApp keys are all set (unrelated to MSG91 path).

## Root cause
`MSG91_SENDER_ID` is empty in the production backend environment, so `_msg91_ready()` returns False and every SMS attempt (including the POS billing receipt) short-circuits to "not_configured". `MSG91_FLOW_ID` is also empty, and the billing/booking template IDs (`MSG91_TPL_BILLING_V2`, `MSG91_TPL_BOOKING`) are absent — so even if the readiness gate were passed, the billing-receipt template would not resolve from env.

Note: backend logs show `sms - INFO - HQ MSG91 template IDs applied from hq_settings`, i.e. template IDs are loaded from HQ settings (DB) at runtime, but the readiness gate itself checks AUTHKEY + SENDER_ID from env. SENDER_ID being empty is what blocks send regardless.

## Restart / when-changed note
Production secrets are materialized into the pod environment at deploy time (write_secrets step) and only take effect on a (re)deploy — pods are not hot-reloaded. In the currently serving run (deployed 2026-09-27), `MSG91_SENDER_ID` and `MSG91_FLOW_ID` are empty. So either they were never set in the Secrets tab, or they were edited AFTER 2026-09-27 without a subsequent redeploy. Any secret change requires a redeploy for the backend to pick it up.

## Fix (User — cannot be done by this agent)
In Deployment Panel → Secrets, set non-empty production values for:
1. `MSG91_SENDER_ID` (required — clears the "not_configured" gate)
2. `MSG91_FLOW_ID`
3. `MSG91_TPL_BILLING_V2` (billing receipt template) and `MSG91_TPL_BOOKING`
Copy the same working values used in preview. Then **redeploy** so the new env is written into the pod, and test a POS billing again.
