## Assessment
- Credentials are configured correctly (both OAuth secrets set), and OAuth token exchange succeeds (that is what sets the "Connected — waiting for approval" status).
- The failing calls are the Business Profile discovery endpoints (`.../v1/accounts` and `.../v1/{account}/locations`). Their failure is logged only at WARNING at connect time and did not recur in the last 24h, so the precise HTTP status/reason cannot be quoted from current logs.
- Based on the app's own status semantics ("API access may be pending approval"), the most probable cause is Google-side: the **Business Profile APIs are not enabled** in the tenant's Google Cloud project and/or the project has **not been granted Business Profile API access** (Google's manual approval), which surfaces as `403 PERMISSION_DENIED "…has not been used/enabled…"` or quota-0 `429`. This is **not confirmed by a log line** and remains a hypothesis until fresh logs are captured.

## Recommended next steps
1. **Google Cloud (tenant / third-party):** In the Google Cloud project backing these OAuth credentials, ensure the **My Business Account Management API** and **My Business Business Information API** are enabled, and confirm the project has been approved for Business Profile API access (Google's access-request form). Until Google grants access, discovery returns 403/quota-0 and the UI correctly shows "waiting for approval."
2. **Capture the exact error (recapture within retention):** Re-trigger the Connect flow in Settings → Connected Accounts, then re-run this log diagnostic **within 24h** so the `google business discovery failed (...)` WARNING and any googleapis 4xx are inside the retrievable window and can be quoted verbatim.
